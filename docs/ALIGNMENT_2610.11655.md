# 与 arXiv:2610.11655 的对齐检查

对照对象：*Harness Evolution Hits a Ceiling: When Weight Training Should Begin*
（`docs/refs/harness-evolution-ceiling-2610.11655.pdf`）。逐项核对我们的设置是否一致、
哪里有意偏离、哪里是还没做到。

## 1. 逐项对照

| 维度 | 论文做法 | 我们的设置 | 结论 |
|---|---|---|---|
| 打分 | DeepPlanning 自带**程序化打分**（硬约束） | 自造 TaskSpec / 复用官方 oracle（AgentDojo 的 `security()`、AgentHarm 的 grading 函数、ASB 环境状态、AutoControl 状态谓词） | ✅ 同方向；**覆盖度不足**（AutoControl 只有 3/70 authored） |
| 切分 | 120 任务**一次性**切 48 dev / 72 held-out；决策只用 dev | 每来源 **30 dev / 30 held-out**，一次性、任务级、按类别分层、同族不跨 | ✅ 原则一致；比例按多来源调整（等额以配合等权） |
| held-out 纪律 | 只在报告时测一次 | 协议写死同样规则 | ✅ |
| 噪声协议 | 先测 σ：σ=0.023（26 个同夜格，最差 0.042）；每配置 **4-rollout 均值**；差异 < **0.035** 视为噪声；**每次接受编辑后重测 fresh anchor** | 公式照抄 `line = 2σ√(2/n)`；**σ 尚未测**（无卡） | ⚠️ 方法一致、**尚未执行** |
| 编辑面 | prompt 文件 / 策略参数 / middleware / 工具 | 已支持 prompt、工具钩子、middleware 检查、工具定义接口 | ✅ 基本一致 |
| 进化循环 | 证据包 → **2 个候选编辑**（各带 manifest + 回滚条件）→ 对当轮 anchor 用 house rules 判（均值跌 >0.02、健康率跌 >0.05、未提交/重复调用率涨 >0.05）→ 留优者 → fresh anchor | **只有评测半边**：配对 A/B（H0 vs H0+Δ）、转移表、TP/FP、按来源等权 | ❌ **未实现提案循环**（designer/critic/cascade/analyzer） |
| 失败分类 | **F1–F4**：按"能消掉它的杠杆"，由**过程信号 + scorer** 的确定性 checker 算，取首个触发 | **Δ 反应向量**：直接测"哪个干预能修好它"，不预设 risk 类别 | ⭕ 同一根轴（按杠杆），但**可信性来源不同**：论文是廉价代理，我们是干预实验 + 见证 |
| 证据包 | 分数 / 健康率 / F1–F4 计数 / 过程指标 / 最差案例；**但从未聚合 scorer 的失败构成**（§6.2 因此卡在 F4） | 协议要求：**每来源固定配额的最差案例 + 失败构成** | ✅ 我们主动吸收并修正了它 §6.2 的教训 |
| 权重训练 | LoRA（rank 32、dropout 0.05、只算 assistant token）在**进化后 harness** 的轨迹上；**安慰剂对照**（打乱回答）；rank 消融；全参对照 | `evolve/policy/DESIGN.md` 有完整设计（三桶 + 反事实样本 + 2×2 交叉 + 安慰剂） | ⚠️ 设计对齐、**未执行** |
| 泛化轴 | **9 条线 × 8 个模型 × 6 个家族 × 2 个基准** | **1 个 victim（Qwen3.5-9B）× 4 个基准** | ⚠️ 模型轴缺失，基准轴更宽 |
| 交叉评测 | 种子/进化 harness × 基座/adapter | 已在协议里定义 2×2 | ✅ 设计一致 |

## 2. 三处**有意偏离**（及理由）

1. **多来源取代单基准**。论文单基准（DeepPlanning），所以不需要处理不均衡；
   我们有 4 个来源，因此必须引入 §3.1 的**等权宏观平均 + 分来源判定线 + 每来源证据配额**。
   这是新增维度，不是偏离方法本体。
2. **失败类型用"直接干预测量"而非"过程信号代理"**。论文的 F1–F4 便宜、确定性强，但它测的是
   *代理*；我们的 Δ 反应向量测的是*真实的杠杆*——更强，但**依赖 Δ 库覆盖度**：库不全，
   类型空间就被截断（这是我们方法的主要风险，需要在报告里说明）。
3. **Δ 库先固定成"公共核心 + 每来源特化"**（统一 5 arms）。论文让提案者自由改 harness，
   不做库约束；我们为了**跨来源可比**先固定一批。扩到自由提案时必须保证**每来源候选预算相等**。

## 3. 还没有做到的地方（按优先级）

> **方向修正（用户裁定）**：不再以论文 F1–F4 为骨架去迭代分类。分类主轴改为
> **Δ 反应向量**（见 `PROTOCOL.md` §3.3）：失败类型由"对 model+initial harness 与
> model+H0+Δ 的配对反应"实证定义。F1–F4 降级为可选描述字段。

1. **测 σ 与判定线**（论文的第一步；我们一步都没走）。没有它，任何 J/Δ 比较都不成立。
2. **提案循环**：证据包 → 2 候选 → house rules → 接受 → fresh anchor。我们现在只能手工给 Δ。
3. **权重训练与安慰剂对照**（已在 `evolve/policy/DESIGN.md` 设计，未跑）。
4. **模型轴**：论文 8 个模型/6 个家族；我们 1 个。
5. **AutoControl 的 TaskSpec 覆盖度**：3/70 authored（论文的 benchmark 自带 scorer，无需此步）。

## 4. 结论

- **原则层面一致**：程序化打分、一次性切分、held-out 只报一次、噪声底先行、跨 harness 交叉评测、
  按"杠杆"分类失败、以及"证据包要含失败构成"这条教训。
- **执行层面落后**：σ 未测、提案循环未实现、权重训练未跑、模型轴缺失。
- **有意扩展**：多来源等权协议、直接干预式失败分类、统一 Δ 库（公共核心 + 来源特化）。
